# Repository Guidelines

## Project Structure & Module Organization

This repository contains AP Microeconomics lecture material and the scripts used to render it. The primary source document is `AP微观经济学讲义.md`; generated deliverables include `AP微观经济学讲义.html` and `AP微观经济学讲义.pdf`. Unit-level HTML exports live at the repository root as `Unit*_*.html`. Chart assets are stored in `charts/`, with PNG charts generated by `generate_charts.py` and SVG charts generated by `generate_svg_charts.py`. Styling for rendered HTML is split between `style.css` and the `github-style/` support files.

## Build, Test, and Development Commands

- `python build.py`: regenerates charts, converts the lecture Markdown to standalone HTML with Pandoc, and attempts PDF export through Chrome or Edge.
- `python generate_charts.py`: regenerates matplotlib PNG charts in `charts/`.
- `python generate_svg_charts.py`: regenerates SVG charts in `charts/`.
- `python generate_ppt.py`: builds the slide deck from existing chart assets.

Required local tools include Python 3, Pandoc, and a Chromium-based browser for automatic PDF export. Python dependencies observed in scripts include `numpy`, `matplotlib`, and `python-pptx`.

## Coding Style & Naming Conventions

Use Python 3 with 4-space indentation. Keep generator scripts procedural unless a shared helper clearly reduces duplication. Preserve existing chart naming patterns such as `u2_tax_incidence.png` and `u4_game_theory.svg`, where the prefix identifies the unit. Keep source text and generated filenames in UTF-8, and be careful with Chinese paths on Windows; `build.py` uses temporary ASCII filenames for Pandoc compatibility.

## Testing Guidelines

There is no formal test suite in this checkout. Validate changes by running the smallest relevant generator first, then `python build.py` before publishing rendered outputs. After chart changes, inspect the affected files in `charts/` and confirm the final HTML/PDF renders labels, math, and Chinese text correctly.

## Commit & Pull Request Guidelines

This checkout does not include Git history, so no project-specific commit convention is available. Use concise, imperative commit messages such as `Update unit 2 elasticity charts` or `Fix Pandoc HTML styling`. Pull requests should describe the content or rendering change, list the build command run, and include screenshots or exported artifacts when visual output changes.

## Security & Configuration Tips

Do not commit local browser paths, temporary build files, or machine-specific configuration. Keep generated assets deterministic where possible so reviewers can distinguish intentional content changes from regeneration noise.
